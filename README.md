
# 🐒 Rock My Billys

A private pool league app for 7 (or more) players, an Elo-based ranking system,
and a mean monkey mascot that roasts everyone after every match.

Stack: **Next.js (React) + Node API routes + Prisma + Postgres (Neon) + Tailwind**,
built to deploy straight to **Vercel**.

---

## 1. What's in here

- **Login** — username + password only, no sign-up. Admin hands out accounts.
- **Standings** — full league table: Elo, rank tier, W-L, win rate, streak.
- **Fixtures** — see your matches, submit results (winner + win type), wait on
  admin approval.
- **Profiles** — avatar (`/public/avatars/<username>.png`), stats, streaks,
  match history, change your own display name / password.
- **Admin panel**:
  - Create **matchdays**: pick any subset of active players, it auto-generates
    a round-robin fixture list (everyone selected plays everyone else selected,
    once).
  - Approve/certify submitted results — only admin approval actually changes
    Elo and the league table.
  - **Correct** a result after the fact (re-approve with a different winner /
    win type — it cleanly undoes the old Elo change first).
  - Add **guests** (random monkey-breed password generated for them), and
    **promote a guest to a full player** at any time.
  - Deactivate/reactivate players without deleting their history.
- **The Monkey** 🐒 — after every approved result, generates a message for the
  winner and one for the loser based on: who was favored, by how much (Elo
  gap / win probability), and *how* the win happened (normal / sunk the 8-ball
  / whitewash / forfeit). Streaks get extra taunts. He's mean, and he calls
  everyone a monkey. Top of the table is titled **Caesar**, bottom is **Boots**.

Ranks (Elo thresholds), lowest to highest: **Novice → Intermediate → Advanced
→ Veteran → Expert → Master**. Tune the thresholds in `lib/elo.js`.

## 3. Local setup

```bash
npm install

# 1. Create a free Postgres DB at https://neon.tech
# 2. Copy .env.example to .env and paste in your connection string
cp .env.example .env

# 3. Push the schema to your database (no migration files needed for this)
npx prisma db push

# 4. Create the 7 players + admin account
npm run seed

# 5. Run it
npm run dev
```

Visit http://localhost:3000/login.

## 4. Deploying to Vercel + Neon

*Already deployed and just pulled these updates?* Run `npx prisma db push`
again against your database — the schema picked up two new columns
(`winnerPositionAfter` / `loserPositionAfter` on `Fixture`) for the new
activity feed. Nothing else needs to change, existing data is untouched.

1. **Neon**: create a project at neon.tech, grab the pooled connection string
   (`...?sslmode=require`).
2. **Push this code to a GitHub repo** (private is fine, it's just for you 7).
3. **Vercel**: "Add New Project" → import the repo.
4. In Vercel's project settings → Environment Variables, add:
   - `DATABASE_URL` = your Neon connection string
   - `JWT_SECRET` = any long random string
5. Deploy. Vercel runs `npm install` which triggers `prisma generate`
   automatically (see `postinstall` script).
6. **One-time**: run the schema push + seed against your *production* DB.
   Easiest way — run these locally with your `.env` pointed at the Neon prod
   URL:
   ```bash
   npx prisma db push
   npm run seed
   ```
7. Done. Share the URL + the password table above with the group.

## 5. Profile pictures

Drop images into `public/avatars/` named exactly `<username>.png`
(e.g. `neo.png`, `gabriel.png`). The app looks for that file automatically —
no upload feature needed, no database changes. If a file's missing it just
shows the player's initials instead. Re-deploy after adding images (or if
you want people to be able to swap their own pic without a redeploy later,
see the "self-serve avatar upload" idea below).

## 6. How the ranking works (`lib/elo.js` / `lib/monkey.js`)

- Standard Elo, K-factor 32, scaled by win type:
  - Standard win ×1.0
  - Sunk the 8-ball (decisive) ×1.25
  - Whitewash (total domination) ×1.5
  - Forfeit ×0.5 (barely moves anyone)
- Rank tiers are just Elo bands — edit `TIERS` in `lib/elo.js` to retune.
- The #1 player is always labelled **Caesar** regardless of tier name; the
  last-place active player is always **Boots**.
- The Monkey picks his message based on the *winner's pre-match win
  probability* (i.e. was this an upset, a coin-flip, or exactly what was
  expected) plus the win type and any hot/cold streaks. All the trash talk
  lives in `lib/monkey.js` — add your own lines any time.

## 7. Suggested features to add later

**Shipped:**
- ✅ Head-to-head records on every profile.
- ✅ League-wide activity feed on the dashboard.
- ✅ "On this day" streak records — the Monkey calls out personal and
  all-time league win-streak records automatically.

**Still on the list**, roughly easy → bigger lift:

- **Season resets**: snapshot final standings, then reset everyone to 1000
  and start "Season 2" — `RankHistory` table already stores a timeline, so
  a simple "Hall of Fame" of past Caesars is easy to add.
- **Elo history graph** on each profile using the `RankHistory` rows that
  already get written on every approved result.
- **Push/email notifications** when a fixture is approved (Resend or a
  Slack/Discord webhook would be trivial to bolt onto the approve route).
- **Self-serve avatar upload**: swap the static-file convention for a small
  upload endpoint that writes to Vercel Blob storage instead of
  `public/avatars` (needed if you want people to change pics without you
  redeploying).
- **Bracket / knockout matchday mode** as an alternative to round-robin for
  special events, alongside the regular league.
- **Head-to-head "grudge match" requests**: let two players request an
  unscheduled match, admin just has to approve rather than build a whole
  matchday around it.
- **The Monkey gets louder**: streak-based avatar/mood changes, a "roast of
  the week" digest, or hook up the mascot image you're designing so his
  message renders next to an actual illustration per mood (angry, hyped,
  smug, disappointed).
- **Achievements/badges**: "Whitewash king", "Comeback of the season",
  "Most forfeits" (a wall of shame).
- **PWA install prompt** so it behaves like an app on everyone's phone home
  screen — Next.js supports this with a manifest + service worker with very
  little extra code.

## 8. Notes on scope / security

This was built for 7 trusted friends, not the general public — so:
- Passwords are simple and shown/stored in plain text in the seed script
  and admin-created-player API responses (only ever shown once, but do
  write them down).
- There's no rate limiting, no email verification, no "forgot password"
  flow (admin just sets a new one, or the player changes it from their own
  profile once logged in).
- If you ever do open this up beyond the 7 of you, tighten `JWT_SECRET`
  handling, add rate limiting on `/api/auth/login`, and stop returning
  plaintext passwords from the players API.
